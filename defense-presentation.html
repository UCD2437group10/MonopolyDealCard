系统采用 MVC + 分层架构。后端使用 状态机模式（大厅→游戏中→结束）， 前端使用 MVVM（ViewModel 投影后端状态供 View 消费），前后端通过 命令模式（Request-Response over TCP/JSON）通信。

3. 后端 — 数据模型层 Model

3.1 Card 接口 & CardType 枚举 & SimpleCard

文件类型职责
Card.java interface 定义卡牌的四项基本属性：name(), type(), color(), bankValue()
CardType.java enum 五种卡牌类型：PROPERTY, ACTION, RENT, MONEY, MULTI_PROPERTY
SimpleCard.java record Java 14 record 实现 Card 接口，不可变，被全局使用 
// Card.java - 接口定义
public interface Card {
    String name();       // 卡牌名称，如 "Pass Go"、"Forced Deal"
    CardType type();     // 卡牌类型枚举
    String color();      // 颜色："Brown", "Wild", "Light Blue/Brown", "-"
    int bankValue();   // 银行价值: 1-10
}

// SimpleCard.java - 不可变实现
public record SimpleCard(
    String name, CardType type, String color, int bankValue
) implements Card {}
💡 设计思想：Card 是接口 + SimpleCard 是唯一实现的模式，方便未来扩展（如添加特效卡、稀有卡）。

3.2 Player & PlayerState

文件类型职责
Player.java record 不可变玩家身份：id, displayName, bot
PlayerState.java class 可变游戏状态：手牌、银行、房产组、房屋/酒店计数。包含 自动分组逻辑

PlayerState 核心字段与分组算法

public class PlayerState {
    private final Player player;
    private final List<Card> hand;                        // 手牌
    private final List<Card> bank;                        // 银行（已打出的钱）
    private final Map<String, List<Card>> properties;     // 房产组，key="Brown"/"Brown (2)"
    private final Map<String, Integer> houseByColor;      // 房屋计数
    private final Map<String, Integer> hotelByColor;      // 酒店计数
}
💡 关键算法 — 自动分组：当玩家已有完整 "Brown" 组（2张），再打出一张 Brown 房产时， findPropertyGroupForAdd() 会自动创建 "Brown (2)" 新组而不会覆盖原组。 这支持了"一套颜色多组满编"的高级策略。

    String jsnActorPlayerId,          // 发起JSN链的玩家

💡 使用 Java record 确保快照不可变，前端轮询时不会出现并发修改问题。

4.3 BotTurnService — 简单AI

贪婪策略：优先打钱→打房产→用最便宜的Action当钱→打行动卡。最多尝试12次，每回合最多3个动作。

void playTurn(GameEngine engine, String playerId) {
    int tries = 0, actionsPlayed = 0;
    while (tries < 12 && actionsPlayed < 3) {
        if (tryPlayMoney(...))   { actionsPlayed++; continue; }  // 1. 优先打钱
        if (tryPlayProperty(...)){ actionsPlayed++; continue; }  // 2. 打房产
        if (bankTotal==0 && tryPlayCheapestActionAsMoney(...))   // 3. 没钱时把Action当钱
        if (tryPlayAction(...))  { actionsPlayed++; continue; }  // 4. 打行动卡
        break;
    }
    engine.endTurn(playerId);  // 每步后检查JSN状态，有等待则暂停
}

5.2 CardMoneyRules — 金钱规则

public final class CardMoneyRules {
    public static boolean canBank(Card card) {
        // MONEY、ACTION、RENT 可以存入银行，PROPERTY/MULTI_PROPERTY 不行
        return card.type() == MONEY || card.type() == ACTION || card.type() == RENT;
    }
    public static void validateBankable(Card card) {
        if (!canBank(card)) throw new IllegalStateException("...");
        if (card.bankValue() <= 0) throw new IllegalStateException("...");
    }
}

5.4 GameCommandService — 命令路由

将15种字符串命令映射到 GameEngine 的具体方法调用，统一异常处理。支持的命令：

每个命令失败时捕获异常并返回 GameResponse(success=false, message=error, state=snapshot)，保证前端不会因异常崩溃。

6. 后端 — 网络层 IO

6.1 通信协议

类类型职责
GameRequestrecord(action, playerId, Map<String,String> payload)
GameResponserecord(success, message, GameState)
NetGameResponserecord网络版响应，GameState替换为NetGameState
NetGameStaterecord网络版快照，PlayerState替换为NetPlayerState
NetPlayerStaterecord网络版玩家状态，Card替换为SimpleCard
ProtocolMapperclassDomain↔Net 双向转换器
💡 为什么需要 Net* 版本？因为 Jackson 序列化需要通过无参构造器/record 来反序列化， 而 Card 是接口类型。Net 层全部使用 concrete record（SimpleCard）确保 JSON 可反序列化。

6.2 GameServer — TCP Socket 服务器

  • 监听指定端口，newLine 分隔协议，每行一个 JSON 请求/响应
  • 支持 两种模式：①本地直连（gameServer.handle(request)）②TCP Socket（runAcceptLoop）
  • 使用 CachedThreadPool 处理并发客户端

6.3 GameClient — 前端网络客户端

  • 本地模式：直接调用 localServer.handle() 跳过网络
  • 远程模式：TCP Socket + JSON 读写
  • send() 方法是 synchronized，保证线程安全

// 实现交换逻辑
private void swapHands(String actorId, String targetId) {
    PlayerState actor = playerState(actorId);
    PlayerState target = playerState(targetId);
    List<Card> temp = new ArrayList<>(actor.hand());
    while (!actor.hand().isEmpty()) actor.removeHandCard(0);
    while (!target.hand().isEmpty()) target.removeHandCard(0);
    for (Card c : temp) target.addToHand(c);
    // 原始target手牌已在swap前保存...
}
